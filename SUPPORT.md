# Support

## Bug reports

For an installed copy of Shocked, the preferred route is **Report Bug** inside Console 3. It sends only after **SEND REPORT** is pressed and is designed to avoid adding the local username, hostname, home path, private destination mailbox, or mail credentials.

If the in-app reporter is unavailable, open a GitHub bug issue after the repository is public. Include the Shocked version, distribution, kernel, CPU model, relevant error text, and the exact steps needed to reproduce the problem.

Do **not** include passwords, API tokens, private keys, account identifiers, unrelated personal files, or unreviewed full-system logs.

## Security issues

Follow [SECURITY.md](SECURITY.md). Do not post exploit details or credentials in a public issue.

## Feature requests

Use the GitHub feature-request form once the repository is public. Describe the problem or workflow first, then the requested behavior.

## Installation problems

See [INSTALL.md](INSTALL.md) and run:

```bash
shocked-ctl doctor
```

Include the relevant diagnostic output in a report after reviewing it for information you do not want to publish.
